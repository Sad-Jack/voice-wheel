# Настройки — спецификация (как должно работать)

> Это **дизайн-документ** желаемого поведения окна настроек, не текущая реализация.
> Текущее окно (сгруппированное, с подписями бэкендов и скрытием лишнего поля
> модели) — промежуточный шаг. Здесь зафиксировано целевое видение (Settings v2),
> из которого будем строить.

## Цель

Окно настроек должно быть понятным новичку. Принципы:
1. **Только релевантное** — показываем настройки выбранного способа подключения, остальное скрыто.
2. **Помогает настроить под капотом** — скачать модель/голос, проверить/поставить Ollama, подсказать про ключ.
3. **Объясняет** — тултипы при наведении, понятные подписи, состояние «что не так / что сделать».

---

## 1. Способ подключения LLM — три типа (радио-выбор)

Вместо одного дропдауна с тех-именами — **радиокнопки** (или сегментированный контрол) с тремя базовыми типами. У каждого — **свой набор настроек**, который показывается только при его выборе.

### A. Прямой API (облако) 🔑
Подключение напрямую к облачной модели по API-ключу — самое быстрое и качественное, но платно + нужен ключ + интернет.
- **Провайдеры:** OpenAI (ChatGPT / GPT) и Anthropic (Claude).
  - ⚠️ OpenAI — **новый** бэкенд, сейчас в коде нет (есть только Anthropic). Нужно добавить.
- **Настройки:**
  - провайдер: OpenAI / Anthropic;
  - API-ключ (поле ввода; где хранить — см. «Открытые вопросы»);
  - модель (дропдаун с топ-рекомендациями, см. §4).
- **Как настроить (инструкция в окне):** где взять ключ (ссылка на страницу ключей провайдера), вставить, выбрать модель.

### B. Ollama (локально) 🖥
Локальная модель через Ollama — бесплатно, офлайн, без ключа. Требует установленной и запущенной Ollama.
- **Настройки:**
  - модель (дропдаун с топ-рекомендациями + кнопка «Скачать» → `ollama pull` под капотом, см. §4);
  - URL (по умолчанию `http://localhost:11434`, обычно не трогаем).
- **Проверка состояния (важно):** если Ollama не установлена или не запущена — показать прямо в окне предупреждение **«Ollama не установлена / не запущена»** + ссылку/кнопку установки (§5).

### C. Claude Code (CLI, подписка Max) 🟣
Через установленный `claude` CLI — на подписке Claude Max, без API-ключа. (Так было подключено у владельца проекта.) Дольше в настройке, но кто хочет — подключит.
- **Настройки:**
  - модель;
  - путь к `claude` (авто-определение, поле для ручного переопределения).
- **Как настроить (инструкция в окне):** установить Claude Code, залогиниться (`claude login`), выбрать модель.

> **Маппинг на текущие бэкенды кода:**
> - Прямой API → `anthropic` (+ новый `openai`)
> - Ollama → `ollama`
> - Claude Code → `claude_warm` / `claude_cli`

Показывать только настройки выбранного типа подключения; всё остальное скрыто (а не задизейблено и не висит пустым). ## 3. Тултипы (подсказки при наведении)

У каждой нетривиальной настройки — **всплывающая подсказка** при наведении курсора (`NSView.setToolTip_`), коротко объясняющая, что это и когда применяется. Примеры:
- «Способ подключения» → «Откуда брать ИИ для обработки речи: облако по ключу, локальная Ollama, или Claude Code».
- «Модель» → «Конкретная модель выбранного провайдера. Топ-рекомендации ниже».
- «STT модель» → «tiny/base/small/medium — точность ↔ скорость. small — оптимум для русского».
- «Триггер» → «вид + кнопка/клавиша: mouse_side + 3/4, keyboard + f8, mouse + left».

---

## 4. Топ-рекомендованные модели + установка

После выбора типа подключения — **снизу список топ-моделей**, которые можно поставить/выбрать сразу:
- **Ollama:** список рекомендованных (напр. `qwen2.5:7b`, `llama3.1:8b`, `qwen2.5:3b` для слабых машин) + кнопка **«Скачать»** → `ollama pull <model>` в фоне с прогрессом. После скачивания — модель доступна в выборе.
- **Прямой API:** список рекомендованных моделей провайдера (выбор без скачивания — они в облаке). Напр. OpenAI: `gpt-4o-mini`, `gpt-4o`; Anthropic: `claude-haiku-4-5`, `claude-sonnet-4-5`.
- **Claude Code:** рекомендованная модель (напр. `claude-haiku-4-5`).

Идея: пользователь выбрал систему → ему сразу предлагают «вот хорошие модели, нажми — поставим».

---

## 5. Установка Ollama

Если выбран тип **Ollama**, но она не установлена:
- показать заметную плашку **«Ollama не установлена»** + кнопку/ссылку установки:
  - ссылка на https://ollama.com/download, и/или
  - подсказка `brew install ollama` (если есть Homebrew);
- (опционально, на подумать) предложить **установить автоматически** — но это требует прав/Homebrew, поэтому скорее ссылка + инструкция, чем тихая авто-установка.
- если Ollama установлена, но не запущена — подсказать запустить (`ollama serve` / приложение).

---

## 6. Первый запуск

- При **первом запуске** — заметная подсказка, что нужно **настроить под капотом**: выбрать способ подключения LLM и скачать модель (и голос — уже делается, см. фичу #24). До настройки — приложение не падает, а понятным текстом говорит, что сделать.
- Цель: чтобы свежий пользователь не оказался перед молчащей программой или ошибкой, а получил чёткий онбординг: «1) выбери способ подключения, 2) скачай модель, 3) готово».

## 7. Инструкции по настройке (внутри окна, per-type)

Короткий блок «как настроить» для каждого типа, видимый при его выборе:

- **Claude Code:** установить Claude Code → `claude login` → выбрать модель.

## Открытые вопросы / решения на потом

- **Хранение API-ключа.** В `config.json` открытым текстом — небезопасно (файл может попасть в бэкап/гит, хоть и в .gitignore). Лучше — macOS **Keychain** (сложнее) или переменная окружения `.env` (уже поддерживается для `ANTHROPIC_API_KEY`). Решить до реализации «Прямой API».
- **Авто-установка Ollama** — нужна ли вообще, или хватит ссылки + инструкции. Авто-установка требует Homebrew/прав — рискованно.
- **OpenAI-бэкенд** — новый код (клиент `openai`, формат запроса, добавить в `core/llm.py` как бэкенд `openai`).
- **Прогресс скачивания** модели Ollama/Piper — как показывать в окне (плашка/прогрессбар).
- **Применение без перезапуска** — сейчас всё применяется после рестарта; для онбординга, возможно, стоит применять часть на лету.
